# Candidata v1-candidate-20261106-040 (lector de tweets con la API oficial de X)

Estado: **publicada y desplegada**. Rama `feat/lector-api-x` (desde `main` 4aa7430). Sin migración. No hay imágenes publicadas
ni digests todavía.

Incluye: `XApiReader` (`src/nicheradar/integrations/x_api.py`), variables `NR_TWEET_READER` (`fxtwitter` por defecto o `xapi`) y
`NR_X_API_BEARER_TOKEN`, selección del lector en el worker, códigos `reader_not_configured`, `reader_unauthorized`,
`reader_rate_limited`, `reader_credits_depleted` y `reader_blocked` (el 403 de Cloudflare de FxTwitter ya no es
`tweet_unavailable`) y la ayuda «Si no se puede leer» sin culpar solo al tweet.

## Costo y límites (docs.x.com, 2026-11-06)

US$0,005 por post leído y US$0,010 por usuario devuelto (X cobra por recurso); pago por uso con créditos comprados por
adelantado; 450 lecturas por 15 minutos con Bearer app-only. El lector pide el autor solo cuando la URL no lo trae
(`/i/status/<id>`); la expansión de medios se mantiene (no está claro que sea gratis).

Costo: ≈ US$0,005 por lectura (hasta ≈ US$0,015 si hay que expandir el autor; confirmar en el panel de uso de X tras la primera lectura). Techo diario en el peor caso: 50 × US$0,015 = US$0,75/día (≈ US$22/mes). Se recomienda fijar un límite de gasto
en el Developer Console. Sin reintentos automáticos de lecturas fallidas.

Matiz del tope diario: `lead_reads_per_day` (50) cuenta en 24 horas móviles, incluidas las lecturas fallidas y las imágenes;
X deduplica el cobro por día UTC, así que no coinciden exactamente.

## Variables para `nicheradar-worker` (la API y el dashboard no las necesitan)

```
NR_X_API_BEARER_TOKEN=<Bearer token de la app de X>
NR_TWEET_READER=xapi
```

Cómo conseguir el token: ver `docs/subniche-discovery.md`, «Lector de tweets».

**Valor de `NR_TWEET_READER`:** usar exactamente `xapi` o `fxtwitter`. Un valor inválido (por ejemplo `XAPI` en mayúsculas)
tumba el arranque de todo el worker (la validación de configuración falla).

## Orden de despliegue

1. Publicar las tres imágenes de esta rama (con aprobación del propietario) y desplegar la API, el worker y el dashboard
   (la API y el dashboard cambian solo por los textos de error).
2. Cargar las dos variables en `nicheradar-worker` y reiniciarlo.
3. Compartir un tweet de prueba desde el teléfono y comprobar la lectura (consume una lectura, ≈ US$0,005).

## Rollback

Poner `NR_TWEET_READER=fxtwitter` en `nicheradar-worker` y reiniciarlo (vuelve a FxTwitter, que hoy da `reader_blocked` desde
la IP del servidor, es decir, la lectura de tweets no funciona y queda el respaldo de compartir la imagen). El token puede
quedar cargado. Sin migraciones. Para volver al código anterior: digests de la 039.

## Riesgos

- El token es una credencial de pago: quien lo tenga puede gastar créditos. Cargarlo solo en el worker, con un límite de gasto
  en el Developer Console; rotarlo si se filtra. No aparece en URL, logs, `repr`, errores ni en el JSON del tick (probado con
  una secuencia centinela).
- No se llamó a la API real (no hay token): la forma de la respuesta se probó con `httpx.MockTransport` según docs.x.com.
  Dudas abiertas: la documentación nueva nombra `post.fields` y `note_post`, el diccionario de datos `tweet.fields` y
  `note_tweet`; se usa `tweet.fields`/`note_tweet`. El HTTP 402 no está documentado.
- Si el saldo se agota, las lecturas fallan con `reader_credits_depleted` (o `reader_rate_limited` si X responde 429).
